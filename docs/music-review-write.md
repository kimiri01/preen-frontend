# 음악 리뷰 작성 화면

브랜치 feature/music-review-create_Moon (커밋·푸시 전).
Must13의 음악 리뷰 작성 링크에서 /accommodations/{id}/reviews/new로 진입합니다.
예약 담당자는 /reservations/{reservationId}/review로 바로 연결할 수 있습니다.

## 화면
- 본인 이용 완료 예약 선택/확인, 별점1~5점 라디오 버튼.
- Spotify 개별 곡 공유 링크/트랙ID/spotify:track URI로 한 곡 선택.
- 공식 iframe 미리보기와 선택 취소. URL을 그대로 iframe에 넣지 않고 검증한ID만 고정 공식 호스트에 조합합니다.
- 잘못된 링크/빈 별점/예약 미확인 상태는 등록하지 않습니다.
- 중복 클릭을 잠그고 등록 중 입력을 비활성화합니다. 실패해도 초안은 유지합니다.
- 성공 시 기존 음악 리뷰 캐시를 갱신하고 전체 리뷰 목록으로 이동할 수 있습니다.
- 날짜·인원 쿼리는 뒤로가기 링크에서 유지합니다.

## 의존 기능
로그인 계약 미정이므로 실제 등록은 막혀 있습니다. 별점/곡 선택은 미리 확인 가능하며 DB에 저장하지 않습니다.
로그인 기능 연결 후 작성 가능 예약 조회가 성공해야 등록 버튼이 활성화됩니다.
음악 검색은 별도 담당 기능입니다. 현재는 링크 입력을 사용하고, 검색 결과의 22자 Spotify 트랙ID를 같은 선택값으로 연결할 수 있습니다.
이 화면은 실제 로그인 성공을 가장하거나 테스트 사용자로 저장하지 않습니다.

API: backend docs/room-feature/review-write.md 참조.
CSRF 토큰은 인증 후 /api/reviews/csrf에서 받아 POST 헤더로 보냅니다. URL/저장소에 보관하지 않습니다.
조회는 기존 리뷰 목록·별점 필터를 재사용합니다. 수정·삭제는 별도 범위입니다.

검증: 프론트 빌드 통과, 날짜/인원4개+곡 링크 검증2개 테스트 통과.
브라우저에서 Must13→작성,5점 선택,잘못된 링크 거절,공식 플레이어 미리보기,
미인증 예약 안내/등록 비활성화 확인. 실제 성공 화면 왕복은 로그인 연결 후 확인 필요.

## 팀 예약·임시 인증 호환 (2026-11-18)
최신 원격 develop은 frontend 00e5b93, backend 24545a4입니다. 예약 API/임시 인증은 별도 22eac81 브랜치에 있습니다.
프론트 등록 API는 서버가 CSRF 토큰을 발급하면 기존처럼 헤더에 담습니다. 팀 임시 모드처럼 토큰을 발급하지 않는 경우에만 헤더를 생략합니다.
로그인 우회나 userId 전송을 프론트에 추가하지 않았으며, 임시 인증 설정도 켜지 않았습니다.
예약 생성 입력(roomId, checkIn, checkOut, guestCount)은 기존 객실·일정 값과 호환됩니다. 예약 생성/결제 화면 연결은 별도 범위입니다.
팀 공통 화면·공통 요청 모듈·원격 브랜치는 수정하지 않았습니다.
